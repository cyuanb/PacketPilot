# 齐备 · PacketPilot

有依据的材料预检，有条理的申请准备。

PacketPilot 是可自行部署的开源材料准备工作台，将通知、资料、检查结果和补件对话组织在一起。

[English](README.en.md) · [使用说明](docs/usage.md) · [配置说明](docs/configuration.md) · [架构](docs/architecture.md) · [测试](docs/testing.md)

当前版本：0.9.0。软件使用 Apache-2.0 许可；自行配置的模型或基础设施可能产生资源费用。

## 功能

- 创建和管理材料事项，保存通知与材料版本。
- 管理工作空间内的个人／组织主体档案，为事项明确关联申请主体、推荐人、经办人等角色。同名档案分别保存，关联变动会提示重新核对。
- 独立资料中心与收集箱：上传、主体/分类整理、搜索、归档、原件预览和不可变版本历史；相同原件提示重复但不覆盖用户版本。
- 查看资料在事项中的使用位置。资料中心新增版本不会自动改变事项中的材料；从事项移除后原件仍在资料中心保留。
- 从资料中心选择固定版本用于事项，显式接受新版本；同一资料可在不同事项中独立使用。
- 选择教育交流、求职、入职、企业入驻或供应商起步配置，按真实通知用表单建立并确认要求。
- 运行不调用模型的基础预检，跟踪问题和补件进展，复检后解决或重开；例外说明不改变检查结论。
- 提取带原文引用的要求草稿，审阅后启用。
- 读取 PDF、DOCX、TXT、Markdown；保存图片并支持人工校订文本。
- 执行明确字段、格式、页数、日期和内容检查，查看引用与待处理问题。
- 通过工具调用助手进行多轮分析、追问和补件复检。
- 记录人工确认，导出 HTML 或 Markdown 检查清单。
- 检查会验证逐材料字段覆盖、当前要求集合和引擎版本。历史或不完整结果需要重新预检，不能作为当前完整结果导出。

## 快速开始

需要 Git、nvm for Windows、.nvmrc 指定的 Node、Python 3.11+ 和 PostgreSQL。数据库和模型地址通过本地配置提供。

~~~powershell
git clone https://github.com/cyuanb/PacketPilot.git
cd PacketPilot
Copy-Item .env.example .env
~~~

填写 .env 的 DATABASE_URL、LLM_BASE_URL、LLM_API_KEY 和 LLM_MODEL，再运行：

~~~powershell
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
powershell -ExecutionPolicy Bypass -File scripts/start.ps1
~~~

打开 http://localhost:8010。登录账号由 OWNER_USERNAME 配置，密码见本地 OWNER_PASSWORD。初始化时密码为空会生成随机密码，不存在通用默认登录密码。

停止应用：

~~~powershell
powershell -ExecutionPolicy Bypass -File scripts/stop.ps1
~~~

脚本以原生进程运行，不依赖 Docker，不停止共享数据库服务。已有数据库用户可复用，但应使用单独的应用数据库。

## 使用流程

创建事项 → 导入通知 → 提取并启用要求 → 上传资料 → 预检与查看证据 → 补件复检 → 人工确认 → 导出清单。

“体验一个示例申请”使用虚构机构与合成资料，事项可独立修改和删除；对应资料原件仍由资料中心保留。

## 当前限制

- 本机 CPU OCR 支持清晰中英文印刷体图片和扫描 PDF；需先准备模型。手写、印章与复杂表格仍需人工复核。材料类型候选不是真实性鉴定，不提供自动提交。
- 规则检查针对明确可读取的内容；非标准版式、未知条件或识别不足应保留待确认状态。
- 原件保存在本机，必要文本片段会发送到配置的模型服务；不是默认完全离线应用。
- 适合本地单所有者使用。对外部署需要独立验证权限、网络与运行条件。
- 检查清单帮助准备材料，不保证机构受理或其他审批结果。

### 材料交付与深入核对

- 在“材料包与交付”选择当前材料版本、命名和排序，预览后冻结 ZIP；包内含实际文件、目录和 SHA256 manifest。后续变更不改写冻结包，提交/回执由用户单独记录。
- 在“解析与校订”对照逐页原件、OCR 区域和字段候选。重新解析及逐字段/逐页校订追加解析版本，历史证据保持指向原版本。
- 在“材料归属”确认类型、主体、槽位、出具方与原件/译件配对，再配置分主体规则。要求树支持全部/任一/至少若干项、数量独立性、条件和日期窗口。
- 可视化编辑器支持草稿试运行、多来源参数冲突提示、来源有效日期；场景更新需要显式接受。九种起步配置均以用户提供的具体通知为准，不代表正式行业规则库。

可选 OCR 模型准备（Windows 原生环境，已安装后端依赖）：

```powershell
.\.venv\Scripts\python.exe scripts\setup_ocr.py
```

该步骤仅下载固定版本的公开模型并验证 SHA256。日常识别在本机 CPU 执行，不上传图片、不下载模型；配置 `OCR_ENABLED=false` 可关闭。详见 [材料核对与交付](docs/material-review.md)。

### 持续任务与基础协作

当前免费预览版支持任务/草稿、期限提醒、日历、PDF/图片派生加工、限定材料分享/收集与复核、会话撤销和离线恢复码，以及配对数据备份/副本恢复和引用保护下的永久清除。详见 [协作与数据管理](docs/community.md)。真实用户试用及正式场景验收尚未完成，版本保留为 0.x 预览。

### 以助手推进申请

申请默认进入检查概览；齐备助手提供独立一级入口，也可在材料或检查页面打开并排对话。助手使用五份任务 Skill，结合完整对话轮次、历史回查与受控工具完成准备指导、通知提取、预检、复检和依据解释。执行卡片保留实际流程、工具结果及失败状态。详见 [Agent 使用与边界](docs/agent.md)。
