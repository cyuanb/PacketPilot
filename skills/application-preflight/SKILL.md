# 申请材料预检

## 适用范围
用于首次正式核对或查询当前缺件。要求尚未启用时先引导整理通知，不能把场景中的推荐材料当成正式规则。

## 操作流程
1. 调用 get_case_context，检查事项修订号、有效要求、已确认背景、主体、材料读取状态及已有结论；若来源或要求已失效，先指出需要重新确认的版本。
2. 适用条件未知时先调用 ask_user，或用 propose_facts 提议用户刚提供的事实；未经确认不直接写入背景。没有有效要求时停止正式判定并说明如何提取和启用要求。
3. 调用 run_checks 获取当前输入的确定性检查，保留 pass、fail、missing、conflict、unknown 与不适用状态。模型不得覆盖确定性结果，也不得把已索要或已上传当成已解决。
4. 读取语义项对应的材料，按主体、槽位和固定版本限定范围。调用 read_document 逐段读取；has_more 时继续相关段落。不可读、低质量、截断或无法确定归属时保留 unknown。
5. 对语义项逐个检查 parameters.criteria（缺省时以要求标题为检查点）。只有引用确实支持结论，才调用 record_semantic_findings；semantic_coverage 中逐项填写 criterion、verdict、reason、evidence。通过需要覆盖全部对应材料及全部检查点。
6. 汇总程序结果、语义结果和需要本人查看原件的条目。工具失败或执行预算不足时写明未完成范围，不能从已有少量结果推断整个申请已就绪。
7. 按下列格式解释缺件、冲突、未知与下一步，引用“材料名·第N页”的真实片段。说明预检辅助准备，不代表机构审核或真实性鉴定。

## 输出格式
### 本次范围
当前要求版本、材料范围与修订信息；标明未完成内容。
### 发现的问题
按阻塞项、待确认项、建议项组织，写清“什么问题—对应要求—影响”。无问题也不能写官方通过。
### 依据
给出支持每个关键判断的原文位置；缺件判断说明基于当前材料目录，不能伪造缺失文件的引文。
### 下一步
优先给出最多三项可执行行动，人工签名/盖章检查与自动检查分开。

## 禁止行为
不猜测未确认条件、不凭文件名判断材料完整、不用其他主体的字段补缺、不把工具错误改写成成功；不自动启用规则、签署、修改原件或提交申请。
