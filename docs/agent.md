# 与齐备助手一起准备申请

打开申请默认进入检查概览。齐备助手是独立一级入口，也可以在检查、材料或要求页面点击“问齐备助手”，在当前内容旁继续对话。助手按事项隔离上下文，不读取其他事项的聊天或材料。

## 五种任务流程

| Skill | 用途 | 典型入口 |
| --- | --- | --- |
| application-guidance | 澄清目标、续接对话、询问关键条件、准备建议 | “我应该先做什么？” |
| requirement-extraction | 阅读通知并保存有来源的要求草稿 | “请提取通知要求”或 AI 提取按钮 |
| application-preflight | 对已启用要求做确定性与语义预检 | “现在还缺什么？”或 AI 预检按钮 |
| amendment-recheck | 比较补件后的当前结论与旧结果 | “补件后有哪些变化？” |
| evidence-explanation | 解释规则、材料依据和不确定性 | “为什么这条判为冲突？” |

每份流程都在 `skills/<name>/SKILL.md` 中定义触发范围、操作步骤、输出格式和禁止行为。固定操作优先按操作类型选择；对话按明确关键词选择，其他请求使用准备指导。一次运行固定一份 Skill，并记录文件哈希。选择结果可以在助手的执行卡片中看到；多意图请求可能需要分步处理，尤其要求草稿必须由用户先启用。

## 工具与上下文

助手可读取事项背景、分页阅读材料、保存要求草稿、执行规则检查、保存有引用的语义结果、提议背景修改、提出待答问题，以及按关键词回查对话。工具请求被服务端执行，结果以对应调用标识回填模型上下文，直到模型回答或触及预算。

最近上下文按完整的已完成会话轮次重建，最多 12 轮、32000 字符；不把助手的工具调用中间片段拼成用户对话。更早的信息可以使用 `recall_conversation` 回查当前事项的有限匹配片段。系统不承诺无限记忆：找不到信息时应询问用户，而不是补造事实。聊天陈述和模型建议不能自行成为已确认背景。

侧栏显示实际载入的 Skill、历史窗口和已执行工具状态。它记录操作，不展示隐藏推理；刷新后仍可查看最近运行的记录。失败与中断会明确标注，不将“开始执行”显示成“已完成”。

## 使用顺序

1. 导入具体接收方通知，让助手提取要求。
2. 在申请要求中审阅并启用草稿。
3. 上传或引用材料，要求助手检查，并针对不明确的条件继续对话。
4. 确认背景修改建议、补充材料，然后复检变化。
5. 查看证据和人工核对项，最后由自己确认并准备交付。

模型服务不可用时，失败原因保留在执行记录中。基础预检仍可执行明确规则；它不会冒充 AI 语义核验。Skill 被加载、工具循环测试通过，也不等于某次真实模型任务一定按规范完成，需要结合本次执行和输出判断。

官方 DeepSeek 的 OpenAI 兼容入口为 `https://api.deepseek.com`。针对该域名，本项目显式使用非思考模式的工具协议，避免将隐藏推理写入日志或对话。参见 [官方工具调用说明](https://api-docs.deepseek.com/guides/tool_calls/)。具体地址、模型和密钥从本机环境配置读取，文档和仓库不包含个人凭据。
